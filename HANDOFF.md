- **New route POST /api/webhooks/stripe** (placed BEFORE the protected-route interceptor — Stripe sends no Bearer token): verifies the Stripe-Signature header (HMAC-SHA256 over `<timestamp>.<raw body>`, WebCrypto, 5-min tolerance, all v1 signatures tried) against env STRIPE_WEBHOOK_SECRET. No secret → 500 `not_configured`; bad/stale signature → 400 `invalid_signature`; nothing is written before verification passes.
- **Events:** checkout.session.completed activates by buyer email (sets is_subscribed=1 + stripe_customer_id/subscription_id/status); customer.subscription.created/updated sync by stripe_customer_id (active/trialing/past_due keep access, canceled/unpaid/incomplete* revoke) and store current_period_end; customer.subscription.deleted revokes (status canceled). Unknown types → 200 ignored so Stripe never retry-storms.
- **Idempotency:** every event_id is logged in a new stripe_events table BEFORE handling; a replay returns 200 already_processed with no re-activation. Activation itself is a plain SET, so double-delivery is harmless even without the log.
- **Paid-before-registering:** checkout for an email with no account writes a pending_subscriptions row; register, login and /api/auth/me all apply it (activate + store Stripe ids, delete the row). A buyer can pay from the link first and create the account after.
- **Schema:** lazy migrations in ensureSubColumns (same pattern as the trial columns): users gains stripe_customer_id, stripe_subscription_id, subscription_status, subscription_current_period_end; new stripe_events + pending_subscriptions tables. No change to wrangler.json placeholders — secrets are set at deploy, never in the repo.
- **Verified (Node harness importing the REAL src/index.js with a mock D1, payloads HMAC-signed exactly as Stripe signs them): 18/18 PASS** — not_configured without a secret; tampered signature → 400 invalid_signature with zero DB writes; valid checkout.completed → 200 + user activated with Stripe ids; replay of the same event id → 200 already_processed, one stripe_events row; unknown-email checkout → pending row; register after paying → 201 + auto-subscribed + pending row consumed; subscription.deleted → revoked (status canceled); subscription.updated active → re-activated with period end stored (2026-09-21 14:13:20 for test epoch 1790000000); stale (>5 min) timestamp → 400 invalid_signature; unknown type → 200 ignored.
